# OpenAccess MCP API Reference (Current Implementation)

This document describes the API that is actually implemented in this repository today.

## Primary interface

Current callable operations are async methods on `OpenAccessMCPServer` in `openaccess_mcp/server.py`.

### Server construction

```python
OpenAccessMCPServer(
    profiles_dir: Optional[pathlib.Path] = None,
    secrets_dir: Optional[pathlib.Path] = None,
    audit_log_path: Optional[pathlib.Path] = None,
    audit_key_path: Optional[pathlib.Path] = None,
)
```

### Handler aliases

These wrappers call the corresponding `handle_*` methods:

- `ssh_exec(...)`
- `sftp_transfer(...)`
- `rsync_sync(...)`
- `tunnel_create(...)`
- `tunnel_close(...)`
- `vpn_wireguard_toggle(...)`
- `rdp_launch(...)`

## Common return format

Handlers return a dict generated by `ToolResult.model_dump()`:

```json
{
  "success": true,
  "data": {},
  "error": null,
  "metadata": {}
}
```

On failure:

```json
{
  "success": false,
  "data": null,
  "error": "...",
  "metadata": {}
}
```

## Handler signatures

### `ssh_exec`

```python
await server.ssh_exec(
    profile_id: str,
    command: str,
    pty: bool = False,
    sudo: bool = False,
    timeout_seconds: int = 60,
    dry_run: bool = False,
    change_ticket: Optional[str] = None,
    caller: Optional[str] = None,
    token: Optional[str] = None,
)
```

Success `data` keys:

- `stdout`
- `stderr`
- `exit_code`
- `session_id`

Dry-run returns `data.plan` and `data.dry_run = true`.

### `sftp_transfer`

```python
await server.sftp_transfer(
    profile_id: str,

    remote_path: str,
    local_path: str,

```

Success `data` keys:

- `direction`
- `remote_path`
- `local_path`
- `bytes_transferred`
- `checksum`


## Profile format

Profiles are loaded from `<profiles_dir>/<profile_id>.json`.

See sample files in `examples/profiles/`.

Key fields:

- `id`, `host`, `port`
- `protocols` (`ssh`, `sftp`, `rsync`, `tunnel`, `vpn`, `rdp`)
- `auth` (`vault_ref`, `file_ref`, `keychain_ref`)
- `policy` (roles, command allow/deny lists, sudo/change-ticket/session controls)

## Authentication behavior in current default configuration

By default, the global auth provider is `NoAuthProvider` (`openaccess_mcp/auth.py`), which returns an admin-like context for development/testing.

## MCP registration note

The server object exists, but `_register_tools()` is currently empty. This means documentation that assumes fully registered MCP tool schemas/endpoints does not match the present implementation.
